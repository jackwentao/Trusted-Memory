# 设计决策

## 2026-11-24 · 本地向量模型选用 BAAI/bge-m3

中文样例用于调试，后续 LongMemEval 使用英文。选择 BGE-M3 可以让两个阶段沿用同一个多语言模型，减少切换语言时需要重新选择和配置模型的工作。向量计算在本机完成，没有按调用次数收取的向量服务费。提取事实仍通过 CommandCode 调用 DeepSeek。

也考虑了更轻的中文模型 bge-small-zh-v1.5，以及已经跑通的多语言 MiniLM。前者适合中文短句，后者的优势是沿用已有环境。选择 M3 意味着接受更大的模型和本地资源开销。1024 维用于配置存储，维度大小本身不能证明检索更准确。目前没有三款模型的同题对比。

正式对比应记录实际模型，并让需要比较记忆处理方法的各组使用相同的向量模型。结果应标明“Mem0 + 本地 BGE-M3”。如果本机速度或内存成为评测障碍，或在预先固定的中英文题目上经常漏掉相关记忆，再用相同题目比较更轻的模型。

## 2026-11-24 · 主评测集选用 LongMemEval

第一阶段要回答两个问题：事实发生变化后，Mem0 能否答对？答错时，能否根据原话查出信息在哪一步丢失？LongMemEval 单列了知识更新和时间推理题，提供参考答案、证据会话标注，以及同一道题的长对话版本和只保留证据会话的 oracle 版本。我们可以直接按题号比较两种输入，省去自行筛题和整理短版本的工作。[官方说明](https://github.com/xiaowu0162/LongMemEval)

知识更新题 `6a1eabeb` 中，用户先说 5 公里个人纪录是 27 分 12 秒，后来在训练计划中提到，希望打破 25 分 50 秒的个人纪录。参考答案是 25 分 50 秒。如果只给证据会话能答对、换成长对话却答错，就沿着第二段原话核查实际保存、查回和用于回答的内容。如果两次都答错，可以检查提取时是否把已有纪录误写成未来目标。以上是查错方法，本项目尚未运行这道题。[官方题目数据](https://huggingface.co/datasets/xiaowu0162/longmemeval-cleaned/blob/main/longmemeval_oracle.json)

LoCoMo 同样提供证据标注，适合作补充。针对本阶段的知识更新对照，LongMemEval 已经备好题型和成对输入。以后若重点研究对话长度如何影响记忆，优先考虑 BEAM 的多个长度档位。若重点转为助手执行任务时能否用对记忆，再考虑 DolphinBench。

## 2026-11-24 · Phase 1 的可见性和版本规则

事实以用户和属性分组，生效区间左闭右开。用固定事实编号重试，系统保留首次接收时间。相同属性和生效时间有不同版本时拒绝歧义，不按到达顺序猜测。同一条事实先登记为待写，向量端按编号写入成功后才发布。失败后重开数据库可取回待写记录。Phase 2 检索向量后必须经 SQLite 核准可见性和有效区间，再对有效候选按时间加权。离线测试模拟向量已写入但确认丢失。

## Phase 2 读写与复验

D/E 共享抽取、时间归一化与排序。D/E 的抽取提示与 C 组不同，三键白名单也会影响覆盖率，因此 C → D 衡量的是整套改动。拆分归因时需要单独对照抽取策略。当前以声明的当地会话时间为锚点，支持当前、今天、昨天、上个月和 ISO 日期。月粒度使用月初作为排序下界，发生月份内不确定的具体日期查询不返回该住所。先由 SQLite 筛出该用户该时点有效的版本，再用本地 Qdrant 检索，按余弦相似度加 0.05 × exp(-相隔天数 / 365) 排序。参数为初始值。

E 的外部更新返回带编号的 PENDING_REVIEW。自动采纳率按首次决定计，确认后的结果单列。运行集成测试使用以下命令，需项目已有的模型密钥和 BGE-M3。测试在临时目录分别创建 D/E 存储，无需清空已有记忆。

    uv run --locked --env-file .env pytest -m slow tests/integration
